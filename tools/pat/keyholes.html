This is your MQL error taxonomy, live. A student who keeps picking dropped feature needs feature-checklist work; one picking wrong scale needs proportion work. Different fixes.

The four rules

  • Rotation is free. Orientation on the page means nothing — turn it any way.
  • Mirroring is legal. Flipping the object 180° presents the mirrored outline, so a "backwards" match still counts. Two options that are mirrors of each other are therefore both wrong.
  • Interior features don't exist. Holes, slots, grooves, cylinders — if it doesn't touch the perimeter, ignore it. A floating island in an option is an instant kill.
  • Scale is disqualifying. Right shape, wrong proportions is still wrong.
How to drill this for speed
  • Feature checklist first. Name the object's 3–4 signature features before looking at any option. Eliminate on one missing feature.
  • Diff the twins, don't re-scan the object. When two options survive, compare them to each other, find the 2–3 spots they differ, then ask one targeted question of the object.
  • Use "Final two" mode. It removes the three easy eliminations so the student only practises the step that actually decides the item.
  • Speed ladder. Same difficulty three passes: untimed → 20s → 12s. The point is seeing which step breaks first under compression.

Objects are machined solids — a union of large blocks with slots and through-holes cut from them, sampled on a fine grid. The correct option is a computed orthographic silhouette, so every key is exact. Distractors are built by applying one labelled error pattern and are machine-verified to differ from all three true views under every rotation and reflection — so there is always exactly one valid aperture. Stats are in-memory and reset on reload - use Export log to keep a session. The CSV carries one row per attempt with seed, trap type chosen, and seconds, so it drops straight into a tracker. Seeds are shown so any item can be reproduced.
